# 并行写作兼容模式

用于实验、实现或部分评价仍在推进，但作者需要先完成论文、翻译、内部 PDF 或赶摘要截止的情况。它改变写作衔接，不把作者声明或预期升级为已核实事实。

## 进入与声明

用户明确要求“实验与写作并行”“按已声明方案先成稿”“先赶摘要截止”时启用，复用实际消息及授权范围，不另设启用审批点。缺少文件不自动代表获准假设其内容。

从已有材料整理已确定的问题、作者声明的算法与评价协议、实际实现/结果及待补依据。已说清楚的不重复提问；未知设置、种子数、数据规模和比较方向保持未知。

完整工作区使用 `paper-state.json` 的 `drafting.mode=parallel`，以 `evidence/draft-declaration.json` 记录消息依据、允许先写的范围及待填项，格式见 [共享接口](contracts.md)。单段/摘要任务可用简短内部说明，不为调用模式建立整篇论文的空登记。

既有框架确认复用。作者明确授权先写讨论草稿时可推进该范围，不据此批准最终贡献、结果或投稿；实质研究主线改变时只确认受影响决定。

## 先把论证和结构写完整

按成熟论文组织问题、方法定义、公式、伪代码、相关工作、实验协议、图表安排和讨论位置。作者声明的算法可完整定义为设计对象，不因代码尚在实现就只能写背景；与当前实现的差异留在内部账本。

方法可用“本文提出”“我们定义”“该机制通过……”及自然英文，不必把整篇改成项目计划。评价协议描述评价对象、指标和比较问题；代码跑通、协议执行、观察结果及理论证明仍各需依据。成熟表达不意味着用完成时叙述未发生的事件。

正文不反复插入“实验尚未完成”“结果有待验证”等工作进度说明。待办与实现差异留在内部记录；科研上影响结论的适用条件、已知负结果和重要局限仍保留，不能当作进度说明删掉。

| 材料 | 内容 |
| --- | --- |
| 当前中文/英文稿 | 完整学术结构与论证，未知结果处保留 `[[RESULT:R1]]` 等可检索占位。 |
| 内部声明与待填账本 | 消息依据、设计声明、当前证据、实现差异、关联主张和待补依据。 |
| 作者交接说明 | 本轮实际写了什么、哪些事实仍待核、下次局部更新哪些位置。 |

## 结果待补怎么写

- 真实部分结果只按其实际数据、协议、种子、阶段与指标描述，不推广为完整评价。
- 未观测的数字、排名、比较方向、显著性、效率优势、消融作用和泛化结论用结果位；不填合理猜测、演示数字或假图。
- 每个结果位关联唯一账本 ID、主张 ID、文稿位置及待补证据；未知结果的解释也留待填，不先编“为什么获胜”的故事。
- 现在可写实验问题、表格结构、指标定义与分析维度。没有运行依据时，不把这些协议写成“实验表明”“已经验证”“we demonstrate”。
- 声明不改变证据级别：author_reported/planned/synthetic 不能变成 observed，经验性候选主张仍为 unresolved，不能改标签绕过检查。

| 场景 | 可用写法 | 需要实际依据后才能使用 |
| --- | --- | --- |
| 方法已声明 | “本文提出通过 A 联结 B 与 C 的框架。” | “完整实现已验证正确。” |
| 评价协议已定 | “评价协议包含准确性、时效性与计算开销三个维度。” | “全面实验验证了三个维度的优势。” |
| 结果未知 | `[[RESULT:R1]]`，结果到达后补真实方向及幅度 | “显著提升 8.3%”“在所有数据集上最好” |
| 英文方法 | “The mechanism is designed to …” | “The mechanism has been shown to …” |

## 摘要截止的两个版本

阶段 0 先查目标年份/track 的摘要与全文截止、字段要求、修改/锁定规则及结果内容要求。不预设摘要之后一定能改，或所有会议接受相同做法。

优先写**结果中性摘要**：完整表达问题、已定义方法、机制、设计贡献和范围，不提内部排期，不含未知数字和未观察的比较结论。贡献必须由真实定义、推导、实现或已有证据支持，不能靠删结果句掩盖不存在的方法。

另可保留**内部完整摘要草稿**，结果句使用 `[[RESULT:R1]]` 等占位，便于后续替换。带占位的版本不能标为可提交；结果中性摘要也不能在未核对会议要求时宣称合规。要求必须提供结果时，说明具体缺项，同时交付可写部分。

按需保存 `manuscript/abstract.registration.zh.md` / `.en.md`、`manuscript/abstract.internal.zh.md` / `.en.md`，不创建空文件。不代作者向投稿系统提交。

## 自审、英文与内部 PDF

两轮自审照常：设计与论证问题现在修正，缺少 R1 的结果记为待补，不伪称已解决。单项缺口不能让全篇反复停在同一门禁。

已授权的英文修订与内部 LaTeX/PDF 可继续，保留占位 ID、限定范围、证据强度和真实数值；不把“设计用于”润色成“实验证明”。内部 PDF 的名称或交接说明标明草稿性质，结果位保持可见，不能藏进注释后假称已解决。

默认 `paper_workspace.py check --stage N` 的严格行为不变。完整工作区可用例如 `check --stage 3 --purpose draft`（也支持阶段 4、5）检查声明、待填项与草稿接口，不改变状态/证据，不证明作者批准或投稿就绪。阶段 5 仍需真实构建、PDF 和输入绑定；未做视觉检查不记通过。

草稿检查仅用于继续写作；严格检查发现的真实矛盾仍需修正，未齐事实登记后继续独立部分。不要把“草稿接口一致”称为“研究真实性通过”。

## 结果到达与投稿前核对

结果到达后核对来源、配置和比较条件，替换对应结果位，只更新相关摘要、表图、讨论和结论。方向不符合预期时改结论，不选择性保留旧故事；不因数值更新重做全文或擅自重跑实验。

投稿前集中核对未决结果位、在用的 unresolved/contradicted 主张、声明与最终实现差异、文稿与真实结果、最新 PDF 及官方要求。只删占位或清空账本不算补证。摘要注册只按摘要实际陈述的主张及当时要求评估，不代表整篇已验收。

原检查逐阶段评估，不能只凭 `check --stage 5` 返回 consistent 宣称全篇可投。最终还需相关内容、引用、翻译与投稿检查；写作成形、构建成功、事实核实和可投稿分别报告。
