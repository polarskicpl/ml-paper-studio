# 调用示例

以下是任务入口示例，不是预先确认、真实结果或固定期刊规则。

## 从研究项目开始

> 使用 $ml-paper-studio。根据这个项目的实际代码、冻结配置和结果，先核实实现与数据，给出中文论文框架、主贡献和证据缺口。我的目标是 ML/AI 会议，具体会议稍后确定。

此任务到阶段 1 的可审阅框架；继续阶段 2 后形成文献定位修订版，再进入作者确认。未确定会议不阻挡通用框架，但不宣称已满足某会议要求。

## 已明确投稿目标

> 使用 $ml-paper-studio。目标是我指定年份和 track 的会议初投。先核对官网规则、获取完整模板，并根据已有研究证据和最近相关工作修订中文框架。

助手需要精确解析用户给出的会议、年份、track、稿件类型与初投/终稿阶段。未来年份未公布时记录 provisional，保留待更新项。

## 只做文献定位

> 使用 $ml-paper-studio 的文献阶段。围绕我的设计检查前置、最接近和竞争工作，区分组件来源与整套机制的关系。给我中文定位、比较矩阵和真实引用；不要新增训练。

默认使用公开术语进行检索；本地未发表材料保留本地。结果是有证据的定位和边界，不是预设新颖性结论。

## 框架确认后继续

> 我确认你刚才给出的这版中文框架及贡献边界。请继续写中文正文，自审和模拟审稿后修订，再完成英文和 LaTeX 交付。

助手记录这条实际消息与确认版本。若该消息确实授权完整后续流程，按阶段 3–5 继续；不会再逐阶段等待“开始”。

## 已有中文稿或 LaTeX

> 使用 $ml-paper-studio，把这份中文方法和实验章节改为学术英文。保留数值、公式、引用附着和结论强度；只在有风险的地方给回译说明。

> 使用 $ml-paper-studio，检查现有 main.tex 和 PDF 的引用、公式、图表与投稿规则，只修这次发现的问题。

已有稿件直接进入相应阶段，复用有效证据和已核实资料，不强制补跑完整 0–5 流程。

## 默认行为

实验仍在推进而需要先成稿时：

> 使用 $ml-paper-studio 的并行写作兼容模式。按我已声明的设计和评价协议先完成中文正文，再翻译和排内部 PDF。工作进度留在内部账本，不在正文反复写实验未完成；未知结果保留关联占位。先给我结果中性的摘要注册版本，结果到达后只更新相关段落。

这会加载 [兼容模块](parallel-drafting.md)。已有授权与框架确认复用，缺少一项结果不会阻断其他写作；不生成假数值、假结论或默认替作者提交。

- 中文框架与中文正文在英文写作之前；中文内容先稳定，再处理跨语言保真。
- 主入口自动选择相关内部阶段，不需要用户记住六个子技能的名称。
- 默认两轮有目的自审，必要时第三轮；不根据语言检测分数或模拟录用概率宣告质量。
- 对缺证据、缺模板、未编译或未视觉检查分别记清状态。只完成源码时如实交付源码，不称 PDF 已完成。
