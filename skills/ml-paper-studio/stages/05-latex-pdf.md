# 阶段 5：LaTeX、PDF 与交付检查

本阶段将已确认的英文论文转为真实、可检查的会议模板工程及 PDF。
编译成功、内容正确、视觉可读和投稿合规是不同检查，分别记录。

## 输入与输出

- 读取 `paper-state.json`，确认阶段 4 的稿件及当前有效目标。
- 主要输入为 `manuscript/manuscript.en.md`、`venue/requirements.json` 和已查证的模板 bundle。
- 从 `template.manifest_path` 解析真实 manifest，再定位该 bundle 内的 `template/`。
- 同时读取 `evidence/evidence-map.json` 与 `evidence/terms-and-symbols.md`。
- 使用已经核验的参考文献记录、图表与标题，不从记忆补造 BibTeX。
- 模板或目标未确认时可以生成草稿工程，但相应合规项不能通过。
- 最终工程为 `paper/main.tex`、`sections/`、`figures/`、`references.bib` 及模板依赖。
- 真正保存的最终 PDF 为 `paper/paper.pdf`，不能只交付预览链接或编译状态。
- 构建记录写入 `checks/build.json`，PDF 检查写入 `checks/pdf-check.json`。
- 最终中文说明写入 `checks/final-report.md`，更新 `paper-state.json`。

## 先确认内容保真

1. 将英文稿中的主要结论、数值和公式与证据账本对应。
2. 核对数据切分、种子数、完整或探索性结果、基线名称及评价方向。
3. 核对绝对变化、相对变化和百分点，保留误差定义与统计计算口径。
4. 表格和图中数字与正文、摘要、结论一致；发现矛盾先定位来源。
5. 不在排版时新编实验、删去负结果、扩大适用范围或改变论证强度。
6. 内容证据不足时保留明确缺口，不能靠措辞或排版让它显得已被验证。

## 公式与数学检查

- 按符号表统一变量、下标、字体约定和随机变量含义。
- 公式使用可编辑 LaTeX；不得用公式截图代替可表达的数学内容。
- 核对符号首次定义、条件、取值范围、单位、维度及与算法的对应。
- 方法公式需对照实际代码与证据：归一化、损失、掩码、更新式和反馈时序。
- 区分作者方法、实际实现、理论推导和解释性简化，不能悄悄混为一谈。
- 推导步骤、定理条件和证明依据无法确认时，标为待核验，不补造证明。
- `equation`、`align` 等环境根据内容与模板选择，长公式不得侵入相邻栏。
- `\label`、`\eqref` 与正文指代一致，避免硬编码公式编号。
- 编译只能证明部分语法和链接可解析，不能证明公式数学正确。

## 组装工程

- 此时才从已绑定 bundle 的 `template/` 复制官方文件到 `paper/`，保留类、样式和 bibliography 文件。
- 把各章节放入 `paper/sections/`，图表放入 `paper/figures/`，路径以主文件为基准。
- 图片、代码片段、引用与 include 仅从授权论文工程范围读取。
- 图片优先保留适合出版的矢量资源；不能将既有低清图伪装为高分辨率。
- 图注、表注、缩写、误差说明、单位与英文稿一致，满足模板的替代文本要求。
- 不修改官方样式参数来缩篇，不用不必要的负间距或微小字号掩盖超页。
- 篇幅不足时精简重复文字或按官方允许方式移动细节，保留正文论证自足。
- 保留引用 key、标签和语义，不进行无必要的全局重命名。
- 检查模板示例、占位符、临时注释和测试图片，不能遗留进投稿版本。

## 编译工具选择

若当前环境提供 `create_latex_project`，新建本地 LaTeX 文档优先用它创建专属项目文件夹；其他环境按官方模板在独立目录建立工程。
已有项目在原位置修改，保留其主文件约定，不重建或覆盖整个项目。
提供 `open_in_codex` 时可用它打开工程，供用户查看源码和自动 PDF 预览。
提供 `compile_latex_document` 时，它读取已保存源码并返回诊断；只有 `success` 表示该次编译成功。
该工具不导出 PDF，打开预览也不等于生成了 `paper/paper.pdf`。
主文件不明确时先检查项目约定；仍有歧义才请用户选择，不能猜另一个主文件。
对明确源码错误最多进行三次定向修复并重编；不以盲目重复构建代替诊断。
工具报告 busy 或 stale-project 时短暂等待后最多重试三次，保存最终状态。
这些应用工具不可用时直接使用下节可用的本地 TeX 工具链；没有可用编译器或项目不受支持时保留源码，继续可执行的内容和静态检查。

## 真实 PDF 的保存

- 确认环境是否提供实际 PDF 导出能力，或已安装可用的本地 TeX 工具链。
- 本地构建优先使用依赖感知的 `latexmk`，按官方模板选择引擎及 BibTeX/Biber。
- 检查自定义构建配置；默认关闭 shell escape，不直接执行未知模板脚本。
- 不因自动检测到中文注释就任意替换已确认的官方编译引擎。
- 只安装确有必要且获环境允许的依赖，不默认要求完整 TeX 发行版。
- 将成功构建出的实际 PDF 保存到 `paper/paper.pdf`，核实可重新打开和完整渲染。
- 保存输入文件、模板、引擎、构建命令、结果和 PDF 的哈希及时间。
- 不能因目录中存在旧 PDF 就认定最新源码已构建成功。
- 不用 ReportLab、普通 Markdown 转 PDF 或截图拼接冒充正式 LaTeX 模板输出。
- 无导出能力只阻止 PDF 完成状态；论文内容、工程和可做检查继续完成。
- 此时最终说明准确列出缺少的工具或导出步骤，不宣称交付 PDF 已完成。

## 增量构建与检查

- 同一源码、图表、文献、模板和环境已有有效构建时直接复用。
- 内容改变后重新构建受影响版本；不要每次清空 `.aux`、`.bbl` 等辅助产物。
- 不同时启动多个写入相同构建目录的编译器或 watch 进程。
- 保存上次成功产物和失败诊断，失败时不能将旧成功状态移给新版本。
- 不重复进行已通过且输入未变化的模板验证或参考文献元数据查询。
- 使用项目提供的静态 helper 前阅读帮助；其输出是范围受限的候选问题。
- 静态脚本不能替代代码语义、数学正确性、文献归因和 PDF 视觉检查。
- 每次修复有明确问题、变更和复查结果，避免无限润色或无效自迭代。

## 源码与机械检查

- 致命错误、缺失文件、未定义命令、缺字、未解析引用和交叉引用分别处理。
- 检查重复标签、重复文献 key、图表引用顺序与正文没有解释的图表。
- 宏、条件编译和复杂 include 无法由静态分析可靠解析时，标记人工检查。
- 区分真实溢出和无害告警，保存影响页及可复现位置，不一概忽略或判失败。
- 检查输出中的 `??`、空白引用、占位文字；文本搜索命中后须检查实际语境。
- 仅在当前官网明确要求时检查特定字体标准、PDF 版本或附件形式。
- 匿名检查覆盖正文、致谢、基金、链接、图中文字、附件和 PDF 元数据。
- 学术自引按投稿规则匿名表达，不删除真正相关的前作以规避身份检查。

## PDF 视觉与合规检查

1. 从真实最终 PDF 渲染全部页面缩略图，检查缺页、空页、顺序和整体密度。
2. 精读首页、公式密集页、跨栏表格、复杂图、正文结束页、参考文献与附录。
3. 检查文字裁切、覆盖、缺字、双栏侵入、孤立标题、图注分离和字号可读性。
4. 核对图表标签、颜色与灰度可辨性、误差条、单位、刻度和面板对齐。
5. 根据规则定义确认正文结束位置，分别统计正文、文献、附录与清单页数。
6. 核对文件大小、必需章节、匿名模式、页码和与 phase 相关的模板开关。
7. 对实际影响布局的修复，重新构建并检查受影响页和全篇页数变化。
8. 最后检查必须绑定最新 PDF 哈希，不能用修改前的截图报告通过。

文本抽取可辅助定位和计数，不能证明视觉排版正确。
没有渲染或图像阅读能力时，将视觉项写为 `not_run` 或 `manual_required`。
摘要字数、正文页数或匿名性无法可靠自动判断时，说明口径并提供人工复查位置。
不把纯审美偏好当成投稿硬性规则，也不靠总评分掩盖必需项失败。

## 完成条件与交接

- `checks/build.json` 记录实际执行内容、构建状态、输入与输出绑定和具体错误。
- `checks/pdf-check.json` 为每项保存 `pass`、`fail`、`not_run` 或 `manual_required` 及依据。
- 存在 PDF 不等于内容或投稿合规已通过；总体状态必须保留未解决项。
- `checks/final-report.md` 给出最新源码、真实 PDF、适用目标、已做检查及待办。
- 可交付草稿和工程；只有实际保存并检查的最新 PDF 才能标记 PDF 交付完成。
- 未执行的检查不写“通过”；模拟审稿不写成真实外部审稿或接收保证。
- 所有交付保持本地可编辑，不自动提交、上传、发布预印本或替用户确认作者声明。
